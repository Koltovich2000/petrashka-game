# Тамагочи Петрашка

Рабочая первая версия Telegram Mini App на React, TypeScript и Vite.

## Открыть игру

В терминале в папке проекта выполните:

```sh
npm install
npm run dev
```

Откройте адрес Local, который напечатает Vite (обычно http://localhost:5173).
Для телефона в одной Wi-Fi сети используйте адрес Network из терминала. Компьютер должен быть включён, сервер — запущен.

## Проверить

- Нажмите кнопку «Погладить»: появятся сердечки.
- Покормите и вылечите его: проиграются анимации. Значения не превышают 100%.
- Нажмите «Поспать»: через 30 секунд добавится 30% энергии. Другие действия на время сна недоступны.
- Через минуту сытость уменьшится на 1%. Обновите страницу: прогресс останется.
- Закройте вкладку и вернитесь позже: показатели учтут отсутствие.
- Интерфейс всегда использует тёмную тему, включая Telegram.
- Здоровье 0% — персонаж погибает. Кнопка «Начать заново» запускает новую игру.

Автоматические проверки: `npm test`. Проверка TypeScript и сборка: `npm run build`. Готовые файлы находятся в dist. Просмотр сборки: `npm run preview`.

## Telegram и Timeweb Cloud

Нужен Node.js 22.16 или новее. Для обычного браузера используйте `npm run dev`, токен бота там не требуется. Полную сборку с сервером можно запустить локально командами `npm run build` и `npm start`. По умолчанию сервер слушает порт 3000. Для локальной настройки используйте `.env.example` как образец для файла `.env`.

1. В GitHub Desktop выберите **File → Add Local Repository** и укажите папку проекта. В **Changes** отметьте исходники, `public/`, `server/` и файлы конфигурации. Настоящий `.env`, `node_modules/` и `dist/` исключены из Git.
2. Введите название коммита, например «Подготовка Telegram Mini App», и нажмите **Commit to main**. Для первой публикации нажмите **Publish repository**. Для уже подключённого репозитория нажмите **Push origin**.
3. В Timeweb Cloud → **App Platform** подключите этот репозиторий и ветку `main`. Выберите **Бэкенд → Другой → Node.js** с версией 22.16+ или 24. Команда сборки — `npm ci --include=dev && npm run build`, команда запуска — `npm start`, путь проверки — `/healthz`. Сервер использует переменную `PORT`, при её отсутствии слушает 3000.
4. В переменных окружения Timeweb задайте `TELEGRAM_BOT_TOKEN` с токеном вашего бота. Храните токен только на сервере. Используйте общедоступный HTTPS-адрес Timeweb в корне домена. Vite собирает клиент в `dist/`, ресурсы доступны по `/assets/…`, а API работает на том же домене по `/api/telegram/auth`. Вкладки переключаются внутри React, отдельных URL у них нет.
5. В [@BotFather](https://t.me/BotFather) настройте **Main Mini App** для своего бота или задайте этот же HTTPS-адрес через `/setmenubutton`. После деплоя откройте игру через бота на iPhone, Android и компьютере. Проверьте вход, нижние кнопки, перетаскивание персонажа и сохранение после повторного открытия.

[Документация Timeweb Cloud](https://timeweb.cloud/docs/apps/deploying-backend-applications) · [Документация Telegram Mini Apps](https://core.telegram.org/bots/webapps) · [Документация GitHub Desktop](https://docs.github.com/en/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop)

### Вход и сохранение прогресса

Официальный SDK передаёт подписанную строку `initData` на сервер. Сервер проверяет HMAC и время выдачи. Для входа данные действуют один час с момента выдачи. Игра получает подтверждённый ID и затем загружает локальное сохранение этого игрока. При ошибке входа игровой экран остаётся закрытым, можно повторить запрос.

- В браузере используется прежний ключ `petrashka:v1`, в Telegram — `petrashka:v1:telegram:<id>`. Локация тоже хранится отдельно для каждого подтверждённого аккаунта. Деньги, одежда, смены и характеристики находятся в основном сохранении.
- Старый общий ключ сохранения остаётся на устройстве. Его нельзя автоматически связать с одним Telegram-аккаунтом. При первом подтверждённом входе открывается новый профиль с интро.
- Сейчас данные принадлежат конкретному браузеру или Telegram-клиенту на данном устройстве и домене. Смена устройства, смена домена и очистка данных влияют на доступность сохранения. Игровое состояние и часы устройства контролируются клиентом.
- Для серверных сохранений нужны серверная сессия после проверки `initData`, база данных с ключом по Telegram ID, авторизованные загрузка и запись прогресса, версии записи для конфликтов между устройствами и резервные копии. Чтобы игрок не мог подменить баланс и результаты, сервер должен сам проверять и начислять изменения по игровым правилам.

## Как устроено

- src/game.ts — расчёт времени, действий и валидация сохранения.
- src/game.test.ts — тесты интервалов, офлайн-прогресса, сна и восстановления.
- src/main.tsx — игровой интерфейс и сохранение.
- src/telegram.ts — адаптация Telegram SDK.
- src/style.css — адаптивное оформление, темы и анимации.

При недоступном хранилище игра показывает предупреждение. Игровое время зависит от часов устройства.

## Гигиена, игра и ограничения действий

Добавлена пятая шкала: гигиена (−1% за 180 секунд, включая отсутствие). «Помыть» даёт +30% гигиены. «Поиграть» даёт +20% настроения и расходует 10% энергии; при энергии ниже 10% действие недоступно. Мытьё сопровождается покачиванием и пузырями, игра — прыжками и мячом. Эффект показывает фактическое изменение с учётом предела 100%.

Перезарядки: погладить — 15 сек.; покормить и поиграть — 30 сек.; помыть — 45 сек.; сон и лечение — 60 сек. Сон по-прежнему длится 30 секунд, его перезарядка отсчитывается от начала. Ограничения проверяются игровой логикой, отображаются на кнопках и сохраняются в localStorage. Нажатие на персонажа использует ту же перезарядку, что и «Погладить». Лечение сохранено для восстановления после обморока.

Старые сохранения версии 1 мигрируют в версию 2 с гигиеной 100% без потери прогресса. Ключ хранилища оставлен прежним. Персонаж пока представлен анимированными 2D-спрайтами с 3D-стилизацией; это не вращаемая WebGL-модель.


## Локации и перетаскивание

Под сценой находятся кнопки «Комната», «Ванная» и «Прихожая». Используются предоставленные изображения из public/assets/locations. Они заполняют окно без искажения пропорций (object-fit: cover); края могут обрезаться на узком экране. Выбранная локация сохраняется отдельно от игровых показателей.

Удерживайте персонажа 300 мс или начните тянуть мышью/пальцем. Он следует за указателем с пружинной инерцией, наклоняется и пугается. При отпускании падает вертикально в выбранной точке, лежит на животе, неловко поднимается и идёт в центр. При смене локации, размера окна или уходе со страницы движение безопасно сбрасывается. Сон и обморок запрещают поднятие. Во время движения уход временно блокируется. Короткое нажатие вызывает реакцию выбранной части тела; поглаживание доступно отдельной кнопкой.

Сцена реализована в src/Room.tsx. Дополнительные позы созданы встроенным image_gen и сохранены в public/assets/petrashka-motion.png; исходный промпт — public/assets/motion-prompt.txt. Анимация использует спрайты, Pointer Events и requestAnimationFrame, без 3D-физического движка. Падение игровое и не наносит урон.


## Опора на пол, шаги и реакции

Фоны выровнены по нижнему краю, ступни стоят на переднем плане пола. Контактная тень остаётся на земле при поднятии. Дыхание меняет высоту корпуса относительно подошв и не поднимает персонажа. Ходьба — четыре отдельных кадра с циклом 0,64 секунды, направление отражается при возвращении слева.

Короткий тап по голове — держится за голову; по животу — держится за живот; по ногам — прикрывает пах поверх одежды; по каждой руке — держит соответствующую руку; по каждой ступне — отдёргивает её. Правая и левая стороны указаны со стороны персонажа (зеркально для игрока). Реакции длятся 1,3 секунды, не отнимают здоровье и не складываются при частых нажатиях. Сон и обморок блокируют реакции. Зажатие/перетаскивание работает отдельно от короткого тапа.

Ассеты созданы встроенным image_gen: public/assets/petrashka-reactions.png (сетка 3×3) и public/assets/petrashka-walk.png (сетка 2×2). Для реакций использован запрос на сохранение внешности персонажа и девять поз: руки на голове, руки на животе, прикрытие паха поверх одежды, поднятие правой/левой ступни, удерживание правой/левой руки, касание правого/левого колена. Затем отдельным запросом удалён белый фон с сохранением сетки и поз. Для ходьбы — четыре последовательные фазы шага влево: контакт правой ноги, перенос левой, контакт левой, перенос правой; прозрачный фон, одинаковый масштаб и линия подошв. Два запасных кадра коленей пока не используются.

## Обновление: смерть, интерфейс сцены и звук

При здоровье 0% персонаж погибает: лежит с закрытыми глазами и крестиками, появляется сообщение «Ваш персонаж погиб - начните заново». Лечение больше не воскрешает. «Начать заново» сбрасывает показатели, возраст, сон и перезарядки к новой игре; выбранная локация остаётся. Это заменяет описанную выше механику обморока.

Локации и пять компактных показателей находятся внутри сцены. Нажатие на показатель раскрывает название и значение; повторное закрывает. Удары можно повторять сразу во время реакции: каждый новый тап перезапускает позу. Уход сохраняет свои перезарядки.

Звуки синтезируются через Web Audio (src/sound.ts): разные тоны для областей тела, поднятия, приземления и каждого действия ухода. Кнопка динамика включает/выключает звук. На телефонах звук становится доступен после первого взаимодействия и зависит от громкости устройства. Голосовые записи не используются.


## Пиксельный интерфейс и гардероб

Интерфейс и три комнаты перерисованы в пиксельном стиле. Кровать стоит слева; в ванной туалет слева, ванна справа, без душевой, сушилки, коврика и ведра. Персонаж стоит на свободном переднем плане пола. Мысли показаны в белом пиксельном облачке. Показатели отображаются заполнением иконок снизу вверх, название и процент раскрываются по нажатию.

Кнопка «Гардероб» под действиями открывает отдельный экран: пять категорий по десять вещей (50 всего). Нажмите вещь для примерки; шапку и аксессуар можно снять. Образ автоматически сохраняется в localStorage под ключом `petrashka:wardrobe:v1`, включая перезагрузку и новую игру. Все вещи бесплатны.

Текущий персонаж использует слоёный SVG с отдельно анимируемыми руками и ногами и растровыми выражениями лица. Это заменяет старые спрайты, описанные в истории выше. Одежда остаётся на нём при движении и реакциях.

Новые фоны: `public/assets/pixel-rooms.png`; лица: `public/assets/pixel-heads.png`. Созданы встроенным image_gen по визуальному референсу. Точные промпты: `public/assets/pixel-art-prompts.txt`. Одежда, иконки и анимации реализованы в коде: `src/PixelAvatar.tsx`, `src/PixelIcon.tsx`, `src/wardrobe.ts`, `src/WardrobeScreen.tsx`.

Проверено: production-сборка, 17 автоматических тестов, примерка и сохранение одежды, раскрытие показателей, мобильная ширина 390 px.

## Этап 1: рубли и работа

Баланс и энергия отображаются рядом с игровым днём. После интро баланс равен 0 ₽. Деньги и активная смена сохраняются внутри ключа `petrashka:v1`, в поле `economy`. Старые сохранения сохраняют текущий баланс.

«Моя жизнь» → «Работа»: раздатчик листовок, 400 ₽/час; смены 15/30/60 реальных минут дают 100/200/400 ₽. Старт списывает 10 энергии, повторный старт блокируется. Уход остаётся доступным по прежним правилам. Таймер хранит абсолютные `started`/`ends`, поэтому работает после закрытия. Закончившаяся смена ждёт кнопки «Забрать зарплату»: баланс, идентификатор полученной смены и удаление активной смены записываются вместе. Повторное получение и перезагрузка не начисляют деньги снова. Начатая смена оплачивается даже если персонаж погиб; новые смены доступны после рестарта.

Остальные профессии закрыты до этапа навыков. Навыки, магазин и цели — заглушки. Ставки и будущие цены — предварительный игровой баланс по заданию, не исследование рынка. Настройки находятся в `src/economy.ts`; конфигурация профессий предусматривает требования, опыт и бонусы для будущих этапов.

Ограничения локального MVP: часы устройства и localStorage контролируются игроком, серверной защиты от подмены времени/сохранения нет. Для игры используйте одну активную вкладку: синхронизация хранилища не является серверной транзакцией. Новая серверная инфраструктура не добавлялась.

Изменения этапа: `src/economy.ts`, `src/Work.tsx`, `src/game.ts`, `src/main.tsx`, `src/Room.tsx`, `src/style.css`, `src/game.test.ts`, `README.md`. Рамки кнопок, карточек, окон, сцены и облачков получили ступенчатые пиксельные скругления. Изображения и одежда сохранены.

## Переезд в Москву и новая игра

Четыре сцены показывают отъезд, поездку, оплату квартиры и начало первого дня. Сумма 65 000 ₽ существует только в диалоге. Кнопка «Начать жизнь в Москве» записывает игру с балансом 0 ₽ и устанавливает `introCompleted` и `rentPaid` в сохранении `petrashka:v1`. С этого момента отсчитываются игровые сутки по 24 часа, включая время вне игры. Прежние сохранения считаются прошедшими интро.

Подтверждение «Начать игру заново» после смерти сбрасывает баланс, смены, показатели, дни, одежду и локацию. При закрытии приложения до окончания интро оно откроется с первой сцены. Покупка зелья пока недоступна. Для цифрового товара в Telegram необходимы Stars и подтверждение платежа на сервере бота. Цена в рублях не может быть зафиксирована внутри Telegram Mini App.

Изменённые файлы: `src/Intro.tsx`, `src/main.tsx`, `src/game.ts`, `src/game.test.ts`, `src/Room.tsx`, `src/PixelIcon.tsx`, `src/style.css`, `README.md`.
