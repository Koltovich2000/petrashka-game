# Тамагочи Петрашка

Рабочая первая версия Telegram Mini App на React, TypeScript и Vite.

## Открыть игру

В терминале в папке проекта выполните:

```sh
npm install
npm run dev
```

Откройте адрес Local, который напечатает Vite (обычно http://localhost:5173).
Для телефона в одной Wi-Fi сети используйте адрес Network из терминала. Компьютер должен быть включён, сервер — запущен.

## Проверить

- Нажмите кнопку «Погладить»: появятся сердечки.
- Покормите и вылечите его: проиграются анимации. Значения не превышают 100%.
- Нажмите «Поспать»: через 30 секунд добавится 30% энергии. Другие действия на время сна недоступны.
- Через минуту сытость уменьшится на 1%. Обновите страницу: прогресс останется.
- Закройте вкладку и вернитесь позже: показатели учтут отсутствие.
- Интерфейс всегда использует тёмную тему, включая Telegram.
- При здоровье 0% Петрашка попадает в больницу.

Автоматические проверки: `npm test`. Проверка TypeScript и сборка: `npm run build`. Готовые файлы находятся в dist. Просмотр сборки: `npm run preview`.

## Публикация в Telegram

Подойдёт хостинг, на котором можно запускать веб-сервис Node.js, задавать переменные окружения и получить общедоступный HTTPS-адрес. Сервер отдаёт игру, файлы `/assets/…` и маршруты `/api/…` с одного домена. Укажите в Telegram корневой адрес сайта. Хостинг только для статических файлов покажет интерфейс, а вход и серверные сохранения требуют запущенного Node.js.

1. **Опубликуйте исходники.** В GitHub Desktop откройте папку проекта через **File → Add Local Repository**, нажмите **Commit to main** и затем **Publish repository** для первой публикации или **Push origin** для обновления. Передавайте на хостинг проект целиком, включая `public/`, `server/` и `package-lock.json`. Git исключает `.env`, `node_modules/`, `dist/` и локальные базы в `data/`. [Документация GitHub Desktop](https://docs.github.com/en/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop)
2. **Создайте веб-сервис Node.js.** Выберите Node.js 24 LTS (минимум 22.16), подключите репозиторий и укажите корень проекта как рабочую папку. Команда сборки — `npm ci --include=dev && npm run build`. Команда запуска — `npm start`. Сервер принимает подключения на `0.0.0.0` и использует порт из `PORT`, по умолчанию 3000. Для автоматической проверки сервиса укажите `/healthz`.
3. **Задайте секреты и хранилище.** В `TELEGRAM_BOT_TOKEN` укажите токен того же бота, через которого открывается игра. В `GAME_DATABASE_URL` укажите строку подключения PostgreSQL с настройками TLS вашего провайдера. Сервер создаст таблицы при первом подключении, поэтому роли БД нужны права на их создание в выбранной схеме. Храните токен и строку подключения в переменных окружения сервера. Для одного экземпляра сервера с постоянным диском можно использовать SQLite и указать `GAME_DB_PATH` внутри примонтированного каталога. Сделайте резервные копии базы. Локальные файлы на хостингах без постоянного диска могут пропасть при перезапуске или обновлении.
4. **Привяжите адрес к боту.** После запуска откройте HTTPS-адрес в обычном браузере и проверьте, что `/healthz` отдаёт `{"ok":true}`. В [@BotFather](https://t.me/BotFather) отправьте `/setmenubutton`, выберите бота и задайте адрес сайта и подпись «Играть». Для кнопки в профиле настройте **Main Mini App**. В BotFather указывается адрес игры, без `/api` и `/healthz`. Запуск Mini App работает независимо от отдельного обработчика сообщений бота. [Документация Telegram Mini Apps](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button)
5. **Проверьте вход и прогресс.** Откройте игру кнопкой бота, выполните действие, закройте и снова откройте игру. Проверьте, что прогресс загрузился, а у второго Telegram-аккаунта своё сохранение. Проверьте запуск на iOS, Android и компьютере. Успешный ответ `/healthz` подтверждает работу HTTP-сервера. Вход и запись прогресса проверяются через Mini App.

Для разработки в обычном браузере запускайте `npm run dev`. Чтобы локально проверить ту же сборку, которая будет на хостинге, выполните `npm run build`, затем `npm start` и откройте [локальную игру](http://localhost:3000). Пример переменных для локального запуска есть в `.env.example`.

### Общий стенд подарков и Telegram Stars

Вкладка «Подарки» обновляет открытую страницу стенда каждые пять секунд. Оплаченные подарки сохраняются в общей базе, а каталог и цены задаются в `server/gifts-store.mjs`. В обычном браузере доступны стенд и каталог. Для покупки откройте Mini App через Telegram.

Подключение платежей можно выполнить отдельно после запуска игры.

1. Укажите строку подключения PostgreSQL в `GIFTS_DATABASE_URL` с TLS по требованиям провайдера. Можно использовать ту же базу, что и для игрового прогресса. Роли нужны права создавать таблицы и последовательности при первом запуске. Для оплаченных подарков используйте постоянное хранилище с резервными копиями.
2. Задайте серверный `TELEGRAM_GIFTS_WEBHOOK_SECRET` из 32–256 букв, цифр, подчёркиваний и дефисов. В `TELEGRAM_PAYMENT_SUPPORT` укажите рабочий контакт для команды `/paysupport`. Для счетов используется уже настроенный `TELEGRAM_BOT_TOKEN` того же бота, который открывает Mini App.
3. Проверьте `getWebhookInfo` и текущий способ получения обновлений бота. Если действующего обработчика нет, установите через `setWebhook` URL `https://ВАШ-ДОМЕН/api/telegram/gifts-webhook` и передайте тот же секрет в `secret_token`. В `allowed_updates` включите `pre_checkout_query` и `message`. Параметр `drop_pending_updates` оставьте выключенным. [Webhook Telegram](https://core.telegram.org/bots/api#setwebhook)
4. Если бот уже обрабатывает обновления, сохраните его текущий обработчик. Передавайте в HTTPS-роут игры запросы с `pre_checkout_query.invoice_payload`, `message.successful_payment.invoice_payload` или `message.refunded_payment.invoice_payload`, начинающимися с `gift:` (подарки) или `hospital:` (старые счета за выписку), а также команду `/paysupport`. Передавайте секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`. Если ответ содержит `method`, верните его Telegram в ответ на webhook либо вызовите соответствующий метод Bot API из существующего обработчика. Возвращайте успех Telegram после успешного ответа сервера игры, чтобы повтор обновления мог завершить запись при временном сбое.
5. Проверьте оплату в тестовом окружении Telegram. После оплаты подарок должен появиться на стенде у другого пользователя. Проверьте также отмену счёта, анонимность и команду поддержки. [Документация Telegram по Stars](https://core.telegram.org/bots/payments-stars)

Для локальной проверки стенд использует SQLite в `data/gifts.sqlite`. На хостинге с постоянным диском SQLite можно настроить явно через `GIFTS_DB_PATH`. Платежи доступны после настройки токена, постоянного хранилища и секрета webhook.

### Вход и сохранение прогресса

Официальный SDK передаёт подписанную строку `initData` на сервер. Сервер проверяет HMAC и время выдачи. Для входа данные действуют один час с момента выдачи. После проверки сервер выдаёт игровую сессию на 12 часов и загружает сохранение по подтверждённому Telegram ID.

- В обычном браузере прогресс привязан к устройству и домену. В Telegram сервер хранит баланс, одежду, характеристики и историю госпитализаций по Telegram ID. Для нового профиля без записи в базе открывается интро.
- Чтобы перенести прогресс на другой хостинг, подключите существующую PostgreSQL или восстановите резервную копию прежней серверной базы. Если прежний сервер использовал SQLite, перенесите её резервную копию на постоянный диск нового сервера. Сохранения из браузера остаются на устройстве.
- Последовательные изменения состояния и запись истории происходят в одной транзакции. Для постоянного размещения используйте PostgreSQL или SQLite на постоянном диске и сохраняйте резервные копии базы.

### Админ-панель

После входа в игру откройте «?» у баланса. Внизу справки показан ваш подтверждённый Telegram ID. В настройках хостинга добавьте серверную переменную `TELEGRAM_ADMIN_IDS` с этим числом. Несколько ID можно указать через запятую. Перезапустите сервер и повторно откройте игру через бота. Кнопка «Админ-панель» появится над нижним меню после интро.

В разделе «Игроки» видны общее количество игроков, активность за 24 часа и список сохранений. Игрока можно найти по Telegram ID или по имени из его последнего входа. В карточке доступны параметры, опыт и начисление игровых рублей. Изменения сохранений записываются в журнал.

В разделе «Подарки» можно менять пожелание и режим анонимности, задавать место на стенде и убирать подарок с витрины. Вручную выставленные позиции имеют приоритет, остальные подарки сортируются по цене. Удаление с витрины сохраняет запись о платеже. В режиме `npm run dev` прежняя тестовая панель работает с локальным сохранением.

## Как устроено

- src/game.ts — расчёт времени, действий и валидация сохранения.
- src/game.test.ts — тесты интервалов, офлайн-прогресса, сна и восстановления.
- src/main.tsx — игровой интерфейс и сохранение.
- src/telegram.ts — адаптация Telegram SDK.
- src/style.css — адаптивное оформление, темы и анимации.

При недоступном хранилище игра показывает предупреждение. Игровое время зависит от часов устройства.

## Гигиена, игра и ограничения действий

Добавлена пятая шкала: гигиена (−1% за 180 секунд, включая отсутствие). «Помыть» даёт +30% гигиены. «Поиграть» даёт +20% настроения и расходует 10% энергии; при энергии ниже 10% действие недоступно. Мытьё сопровождается покачиванием и пузырями, игра — прыжками и мячом. Эффект показывает фактическое изменение с учётом предела 100%.

Перезарядки: погладить — 15 сек.; покормить и поиграть — 30 сек.; помыть — 45 сек.; сон и лечение — 60 сек. Сон по-прежнему длится 30 секунд, его перезарядка отсчитывается от начала. Ограничения проверяются игровой логикой, отображаются на кнопках и сохраняются в localStorage. Нажатие на персонажа использует ту же перезарядку, что и «Погладить». Лечение сохранено для восстановления после обморока.

Старые сохранения версии 1 мигрируют в версию 2 с гигиеной 100% без потери прогресса. Ключ хранилища оставлен прежним. Персонаж пока представлен анимированными 2D-спрайтами с 3D-стилизацией; это не вращаемая WebGL-модель.


## Локации и перетаскивание

Под сценой находятся кнопки «Комната», «Ванная» и «Прихожая». Используются предоставленные изображения из public/assets/locations. Они заполняют окно без искажения пропорций (object-fit: cover); края могут обрезаться на узком экране. Выбранная локация сохраняется отдельно от игровых показателей.

Удерживайте персонажа 300 мс или начните тянуть мышью/пальцем. Он следует за указателем с пружинной инерцией, наклоняется и пугается. При отпускании падает вертикально в выбранной точке, лежит на животе, неловко поднимается и идёт в центр. При смене локации, размера окна или уходе со страницы движение безопасно сбрасывается. Сон и обморок запрещают поднятие. Во время движения уход временно блокируется. Короткое нажатие вызывает реакцию выбранной части тела; поглаживание доступно отдельной кнопкой.

Сцена реализована в src/Room.tsx. Дополнительные позы созданы встроенным image_gen и сохранены в public/assets/petrashka-motion.png; исходный промпт — public/assets/motion-prompt.txt. Анимация использует спрайты, Pointer Events и requestAnimationFrame, без 3D-физического движка. Падение игровое и не наносит урон.


## Опора на пол, шаги и реакции

Фоны выровнены по нижнему краю, ступни стоят на переднем плане пола. Контактная тень остаётся на земле при поднятии. Дыхание меняет высоту корпуса относительно подошв и не поднимает персонажа. Ходьба — четыре отдельных кадра с циклом 0,64 секунды, направление отражается при возвращении слева.

Короткий тап по голове — держится за голову; по животу — держится за живот; по ногам — прикрывает пах поверх одежды; по каждой руке — держит соответствующую руку; по каждой ступне — отдёргивает её. Правая и левая стороны указаны со стороны персонажа (зеркально для игрока). Реакции длятся 1,3 секунды, не отнимают здоровье и не складываются при частых нажатиях. Сон и обморок блокируют реакции. Зажатие/перетаскивание работает отдельно от короткого тапа.

Ассеты созданы встроенным image_gen: public/assets/petrashka-reactions.png (сетка 3×3) и public/assets/petrashka-walk.png (сетка 2×2). Для реакций использован запрос на сохранение внешности персонажа и девять поз: руки на голове, руки на животе, прикрытие паха поверх одежды, поднятие правой/левой ступни, удерживание правой/левой руки, касание правого/левого колена. Затем отдельным запросом удалён белый фон с сохранением сетки и поз. Для ходьбы — четыре последовательные фазы шага влево: контакт правой ноги, перенос левой, контакт левой, перенос правой; прозрачный фон, одинаковый масштаб и линия подошв. Два запасных кадра коленей пока не используются.

## Интерфейс сцены и звук

Локации и пять компактных показателей находятся внутри сцены. Нажатие на показатель раскрывает название и значение; повторное закрывает. Удары можно повторять сразу во время реакции: каждый новый тап перезапускает позу. Уход сохраняет свои перезарядки.

Звуки синтезируются через Web Audio (src/sound.ts): разные тоны для областей тела, поднятия, приземления и каждого действия ухода. Кнопка динамика включает/выключает звук. На телефонах звук становится доступен после первого взаимодействия и зависит от громкости устройства. Голосовые записи не используются.


## Пиксельный интерфейс и гардероб

Интерфейс и три комнаты перерисованы в пиксельном стиле. Кровать стоит слева; в ванной туалет слева, ванна справа, без душевой, сушилки, коврика и ведра. Персонаж стоит на свободном переднем плане пола. Мысли показаны в белом пиксельном облачке. Показатели отображаются заполнением иконок снизу вверх, название и процент раскрываются по нажатию.

Кнопка «Гардероб» под действиями открывает отдельный экран: пять категорий по десять вещей (50 всего). Нажмите вещь для примерки; шапку и аксессуар можно снять. Образ автоматически сохраняется в localStorage под ключом `petrashka:wardrobe:v1`, включая перезагрузку и новую игру. Все вещи бесплатны.

Текущий персонаж использует слоёный SVG с отдельно анимируемыми руками и ногами и растровыми выражениями лица. Это заменяет старые спрайты, описанные в истории выше. Одежда остаётся на нём при движении и реакциях.

Новые фоны: `public/assets/pixel-rooms.png`; лица: `public/assets/pixel-heads.png`. Созданы встроенным image_gen по визуальному референсу. Точные промпты: `public/assets/pixel-art-prompts.txt`. Одежда, иконки и анимации реализованы в коде: `src/PixelAvatar.tsx`, `src/PixelIcon.tsx`, `src/wardrobe.ts`, `src/WardrobeScreen.tsx`.

Проверено: production-сборка, 17 автоматических тестов, примерка и сохранение одежды, раскрытие показателей, мобильная ширина 390 px.

## Прогресс и госпитализация

После четырёх вводных заданий у Петрашки 100 XP и 0 ₽. Завершённый сеанс за компьютером даёт 16 XP и до 12 пунктов настроения. Рубли за выполненные ежедневные задания можно забрать в блокноте.

В Telegram состояние игры обслуживает маршрут `/api/game`. Сервер загружает запись из базы по подтверждённому Telegram ID, использует свои часы и проверяет игровые действия.

Для постоянного хранения задайте `GAME_DATABASE_URL` с адресом PostgreSQL. Если эта переменная пуста, используется `GIFTS_DATABASE_URL`. Для установки на одном сервере с постоянным диском можно задать `GAME_DB_PATH`. Локальное значение по умолчанию — `data/game.sqlite`. История операций госпитализации хранится в таблице `petrashka_medical_history`.

При нулевом здоровье Петрашка попадает в больницу. Сервер начисляет 100 игровых рублей за полный час, включая часы вне приложения. При выписке за рубли игра списывает показанную сумму, продаёт указанные вещи по цене покупки, возвращает сдачу и списывает непокрытый остаток. В Telegram два подтверждённых просмотра рекламы выписывают Петрашку с сохранением денег и вещей. В браузере доступна выписка за игровые рубли на локальном сохранении.

### Реклама за выписку

1. Добавьте Telegram Mini App в Adsun как площадку и создайте отдельный рекламный блок формата **Reward** для больницы. Скопируйте его ID. [Подключение Adsun](https://adsun.io/documentation/publisher/quick-start)
2. Задайте серверные `HOSPITAL_ADSUN_BLOCK_ID` и `HOSPITAL_ADSUN_REWARD_SECRET`. В Amvera это переменные на этапе «Запуск». Для секрета используйте всю строку из `openssl rand -hex 32` и пометьте переменную как секрет.
3. В настройках блока Adsun укажите **Reward URL** с действующим HTTPS-доменом игры и тем же секретом. Оставьте квадратные скобки и их содержимое как в примере. [Reward URL](https://adsun.io/documentation/publisher/reward-url)

   ```text
   https://ВАШ-ДОМЕН/api/hospital/ad-reward?key=ВАШ_СЕКРЕТ&userid=[userId]&block=[blockId]&timestamp=[timestamp]
   ```

4. Разверните обновление. После активации блока проверьте в Telegram, что первый просмотр меняет счётчик на 1/2, а второй выписывает игрока без списаний. Режим debug в Adsun не отправляет подтверждение на Reward URL.

## Автоматические сообщения от Telegram-бота

Сервер отправляет игрокам личные сообщения с кнопкой «🎮 Играть». Уведомления работают и при закрытой игре. После `/start` в личном чате с ботом или входа с подтверждённым `allows_write_to_pm` повторный запрос доступа не нужен. Если доступ ещё не подтверждён, после полного обучения появляется предложение включить сообщения через `requestWriteAccess`. Отключение доступно в настройках игры и сохраняется после повторного `/start` и входа.

В Amvera задайте на этапе «Запуск» следующие переменные.

- `TELEGRAM_BOT_TOKEN` — токен существующего бота, секрет.
- `TELEGRAM_MINI_APP_URL` — прямая ссылка на игру в Telegram, например `https://t.me/ИМЯ_БОТА/ИМЯ_ПРИЛОЖЕНИЯ`. Поддерживается также `https://t.me/ИМЯ_БОТА?startapp` для настроенного Main App.
- `TELEGRAM_GIFTS_WEBHOOK_SECRET` — уже используемый секрет общего Telegram webhook, секрет.
- `GAME_DB_PATH=/data/game.sqlite` либо существующее подключение PostgreSQL — постоянное хранилище прогресса и истории уведомлений.

Обновите приложение и запустите сервер командой `npm start`. Проверка очереди запускается вместе с сервером, отдельный Cron Job не требуется. Сервер должен продолжать работать, когда пользователи закрывают игру. Пустая или неверная `TELEGRAM_MINI_APP_URL` отключает отправку.

Общий webhook игры расположен по адресу `https://ВАШ-ДОМЕН/api/telegram/gifts-webhook`. Он проверяет `X-Telegram-Bot-Api-Secret-Token`. Для получения разрешений и блокировок бота в `allowed_updates` нужны `message` и `my_chat_member`. Для оплаты подарков также нужен `pre_checkout_query`. Если обновления принимает другой обработчик, передавайте ему и затем в игру `/start`, `message.write_access_allowed` и `my_chat_member` наряду с существующими платёжными событиями. Сохраняйте текущую обработку платежей и ожидающие обновления. [Telegram Bot API](https://core.telegram.org/bots/api#setwebhook)

Все тексты уведомлений заданы в `server/notification-store.mjs`. Приветствие отправляется один раз после четырёх учебных действий и знакомства со всеми разделами. Предупреждения о показателях срабатывают при значении ≤20 и при нуле, повтор разрешён после восстановления строго выше 30. Одновременные предупреждения объединяются. Во сне, в больнице, во время глобальной паузы и в течение минуты после последнего обращения игрока предупреждения о показателях не отправляются. Обычные сообщения ограничены двумя за скользящие 24 часа, включая приветствие и напоминание о 48 часах отсутствия. Критические предупреждения и голосования учитываются отдельно.

Очередь, настройки и история хранятся в отдельных таблицах `petrashka_notifications`, `petrashka_notification_queue`, `petrashka_notification_worker` в базе игры. Состояние персонажа проверяется существующим офлайн-расчётом с максимумом 12 часов, проверки уведомлений не записывают новый игровой прогресс и не продлевают этот период. Очередь сохраняется при перезапуске, обработчики используют блокировку в базе для нескольких экземпляров сервера.

Ошибка 429 откладывает отправки на `retry_after`. Подтверждённые серверные ошибки Telegram повторяются с задержкой, максимум пять попыток. При 403 отправка пользователю прекращается до нового подтверждённого доступа. В `sendMessage` нет ключа идемпотентности. При сетевом обрыве с неизвестным результатом событие получает статус `unknown` и автоматически повторно не отправляется. Прерванная аварийным завершением сервера отправка остаётся `sending`. Это предотвращает дубли, но отдельное сообщение при таком сбое может быть пропущено.

Для проверки откройте бота, нажмите «Старт», завершите обучение и проверьте приветствие. Затем закройте игру и проверьте сообщения о низких показателях на тестовом игроке. Переключатель в настройках должен прекращать последующие отправки. Старым игрокам, чей `/start` был обработан до обновления, доступ подтвердится при новом входе с `allows_write_to_pm` либо новом `/start`.

## Переезд в Москву и новая игра

Четыре сцены показывают отъезд, поездку, оплату квартиры и начало первого дня. Сумма 65 000 ₽ существует только в диалоге. Кнопка «Начать жизнь в Москве» записывает игру с балансом 0 ₽ и устанавливает `introCompleted` и `rentPaid` в сохранении `petrashka:v1`. С этого момента отсчитываются игровые сутки по 24 часа, включая время вне игры. Прежние сохранения считаются прошедшими интро.

При закрытии приложения до окончания интро оно откроется с первой сцены. После госпитализации Петрашка возвращается домой после выбора способа выписки.
